# Skill Co-Occurrence Mining for Cooperative Employment Planning

**Smart India Hackathon 2026 · SIH26087 · Ministry of Cooperation**
*AI-Enabled Cooperative Capacity Building, ERP & Employment Ecosystem*

Skills are trained one qualification at a time, but employers hire for **combinations**. This application
mines **which skills genuinely occur together in real job postings** (Apriori and FP-Growth association
rules filtered by support, confidence and lift), ranks those combinations, tracks how they shift over time,
and turns them into **evidence-backed combined training programmes**.

```
REAL JOB POSTINGS → PREPROCESSING → SKILL TRANSACTIONS → ASSOCIATION RULE MINING
                  → LIFT FILTERING → RANKED SKILL COMBINATIONS → TRAINING PLANNING DASHBOARD
```

Generated by `python -m scripts.run_evaluation`; see [`outputs/reports/evaluation_report.md`](outputs/reports/evaluation_report.md).

| Transactions mined (cleaned postings with ≥1 skill) | 670,261 |
| Canonical skills | 239 |
| Frequent itemsets (support ≥ 0.01, length ≤ 3) | 1,002 |
| Rules generated → surviving (confidence ≥ 0.30, lift ≥ 1.2) | 3,944 → 1,386 |
| Apriori vs FP-Growth | identical itemsets and rules; FP-Growth ≈ 1.7× faster |

The frequency baseline alone is misleading: Python and Excel are both top-10 skills, yet they co-occur
**less** than chance would predict (lift 0.59). Meanwhile, 48 of the top 50 ranked rules involve at least one
skill outside the ten most frequent.

## Quick start

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# Processed data is included, so the dashboard runs immediately:
streamlit run app.py
```

To rebuild from the original source (downloads ~67 MB, verifies SHA-256 checksums, preprocesses in ~20 s):

```bash
python -m scripts.download_data    # → data/raw/data_jobs_2023/
python -m scripts.build_dataset    # → data/processed/ + outputs/reports/preprocessing_report.json
python -m scripts.run_evaluation   # → outputs/reports, outputs/results, outputs/charts
python -m pytest                   # 87 tests
```

If `data/processed/` is empty when the app starts, the dashboard offers a **Download and build dataset** button.

### Working in VS Code
Open the folder, choose the `.venv` interpreter (*Python: Select Interpreter*), and use the bundled
launch configurations (*Run and Debug* → **Streamlit dashboard**, **Build dataset**, **Run evaluation**).
The test explorer finds the pytest suite automatically.

## Dashboard pages

| Page | What it does |
|---|---|
| **Overview** | KPIs, most requested skills, strongest combinations |
| **Skill Analysis** | Frequency baseline (top 10/20/30, distribution, transaction sizes), role/country heatmaps, searchable skill explorer, baseline-vs-association comparison, full normalisation trace |
| **Association Rule Mining** | Apriori/FP-Growth, support/confidence/lift/length sliders, configurable ranking weights, filter funnel, ranked rule table with filters, ranking chart, support-vs-confidence scatter, lift distribution, plain-language rule explanations, score breakdown, algorithm comparison, CSV export |
| **Combination Explorer** | Interactive relationship network, co-occurrence heatmap (lift or counts), strongest combinations by size, per-skill rule explorer, extra lift filter |
| **Temporal Analysis** | Quarterly/monthly re-mining, skill trends, rule metric trends, emerging/declining combinations, period comparison, top-K stability |
| **Training Planner** | Select existing skills → complementary skills with evidence, combined programme (modules, prerequisites, target roles, posting counts), role skill-gap, supporting rules, CSV/JSON export |
| **Dataset & Methodology** | Sources and citation, preprocessing report, algorithms and ranking formula, evaluation method, limitations, **upload your own postings CSV** |

All mining controls live in the sidebar (press **Generate rules** to apply); scope filters (role, country)
apply to every page. Every chart has a *View data table* expander.

## Using your own data (e.g. cooperative vacancies)
Dataset & Methodology → *Use your own data*: upload a CSV with a skills column (list or `;`/`|`/`,`
separated) and optionally id, role, title, date, country, employer and location. The same normalisation,
mining, temporal analysis and planner then run on that data.

## Data source
Barousse, L. (2023). *data_jobs* [Dataset]. Hugging Face. https://huggingface.co/datasets/lukebarousse/data_jobs
(Apache-2.0), retrieved in its relational CSV form from a public GitHub mirror. Full details and
alternatives considered: [`docs/DATASET_SOURCES.md`](docs/DATASET_SOURCES.md).

## Important limitations
The verified dataset covers **data and technology roles** in 2023, not cooperative-sector jobs specifically.
The pipeline is domain-independent and accepts any postings CSV. Recommendations describe employer demand
patterns, **not guaranteed employment outcomes**. See [`docs/LIMITATIONS.md`](docs/LIMITATIONS.md).
